# 后台日志与测试版可观测性规范

本规范在酷狗、咪咕、酷我和汽水音乐公开音源补充层完成后实施，属于测试版发布加固，不扩大平台项目范围。当前仅有控制台 `tracing` 输出不能满足部署排障要求。

## 输出与生命周期

- 控制台日志默认启用，适用于前台运行、Docker、systemd 和开发调试。
- 文件日志默认写入 `<TUNEWEAVE_DATA_DIR>/logs/`，可由部署方关闭。
- 控制台与文件分别可配置；服务不能被限制为只支持文件、不支持控制台。
- 支持人类可读和结构化 JSON 格式。
- 文件写入必须非阻塞，不在请求线程同步刷新。
- 支持按日期或文件大小轮转，并可限制保留天数、文件数与总占用。
- 日志文件不得与账户凭证、设备身份或 Uni Playlist 数据混写。
- 正常关闭时尽可能刷新缓冲；写入失败必须通过仍可用的输出目标产生高优先级事件。

至少提供以下环境配置，具体默认文件名可在实现时按现有命名规范固定：

```text
TUNEWEAVE_LOG_LEVEL
TUNEWEAVE_LOG_FORMAT
TUNEWEAVE_LOG_DIR
TUNEWEAVE_LOG_FILE
TUNEWEAVE_LOG_RETENTION_DAYS
TUNEWEAVE_LOG_MAX_FILES
TUNEWEAVE_LOG_MAX_FILE_BYTES
TUNEWEAVE_LOG_MAX_TOTAL_BYTES
TUNEWEAVE_LOG_TO_STDERR
TUNEWEAVE_LOG_TO_FILE
```

默认级别为 `info`；`debug` 和 `trace` 只能显式开启。兼容 `RUST_LOG`，优先级固定为：显式 `TUNEWEAVE_LOG_LEVEL` 高于 `RUST_LOG`，两者都不存在时使用 `info`。所有启动方式使用同一解析逻辑。

当前生产入口已使用同一强类型配置初始化控制台与文件目标：默认同时输出，支持 `human/json`，文件由专用有界后台线程写入并按大小轮转，正常退出持有 guard 刷新缓冲。每次创建新文件前先为完整单文件上限预留空间，按修改时间和稳定文件名从最旧同前缀普通文件开始清理，因此单文件、文件数及同前缀日志总占用同时受严格上限约束；超过单文件上限的单条事件会被拒绝，不会突破总空间边界。启动时另按保留天数清理历史文件，符号链接和无关文件不参与删除。文件名仅允许可移植字符，日志目录在词法路径与现有路径解析后都不得落入账户或 Uni Playlist 数据目录。文件写入器在非阻塞队列计数之外独立记录底层 `write/write_all/flush` 错误；健康监控线程定期读取两类累计故障，发现新增故障时直接输出不含业务数据的最小化应急 stderr 告警。应急事件不再经过可能已经失效的文件 writer，因此不会以监控自身的失败形成反馈循环；即使部署方关闭常规 stderr，文件日志故障也不会静默。

## HTTP 请求关联

所有 HTTP API 经过统一访问日志中间件。服务接收符合格式和长度限制的调用方 request ID，或生成新的安全 ID，并在响应头中返回。内部 provider、后台任务和错误事件必须继承同一关联 ID。

当前统一 Router 已接入请求上下文中间件：只接受单个 1–64 字符的安全 `X-Request-ID`，否则在进入 handler/provider 前以新生成的 ID 返回标准错误；随机 ID、响应头、成功包络与错误包络共用同一个 task-local 值。每个请求建立携带 `request_id/method/route/operation` 的 tracing span，受同一请求 future 驱动的 provider 调用继承该 span；完成事件记录受控 Axum 路由模板、状态和耗时，不读取或记录原始 URI、查询字符串及请求体。二维码轮询与本地媒体内容交付的成功明细降为 `debug`，失败仍按状态输出 `warn/error`。

成功请求至少记录：

- `request_id`、HTTP 方法、路由模板和统一操作名称；
- 平台、响应状态码和总耗时；
- 凭证来源摘要：匿名、服务器凭证或调用方凭证；
- 结果数量、分页是否继续等非敏感摘要。

只记录路由模板，不记录包含真实参数的 URL。不得直接记录原始查询字符串、请求体、Authorization、Cookie、token、密码、手机号、验证码、调用方凭证或媒体临时签名地址。高频轮询、媒体分片和验证码结果查询不在 `info` 逐次刷屏；其单次明细降为 `debug`，事务结束时输出一条汇总。

## 上游请求

每次平台调用至少记录：

- `request_id`、provider 和操作名称；
- 固定上游主机及脱敏后的端点/路径模板；
- HTTP 状态、平台业务码分类和耗时；
- 重试次数、是否使用代理、是否命中受控回退端点；
- 最终成功或统一失败分类。

不得记录完整上游 URL、查询参数、请求体、Cookie、签名、临时媒体地址或完整响应。风控、登录失效、权限不足、资源不存在、限流和上游故障必须落入可检索的统一错误分类，而不是只有自由文本。

## 登录、账户与验证码

允许记录平台、登录方式、凭证归属模式、账户别名不可逆摘要或掩码、事务 ID、二维码状态、会话刷新/替换/退出结果、验证码 provider、切换与重试、challenge 刷新、人工等待、耗时和最终分类。

不得记录 Cookie、refresh/access token、密码、手机号、短信验证码、完整 `gt/challenge/validate/seccode`、TTOCR 服务商密钥、TuneWeave 访问密钥、二维码平台 key 或人工验证结果地址中的敏感参数。不得使用可能包含秘密的完整结构体 `Debug` 输出。

## 错误、启动与关闭

公开错误响应和后台内部错误必须分离。后台错误至少保留 `request_id`、错误分类、阶段、provider、操作、上游状态、重试摘要、安全处理后的错误链、事务 ID 和可重试性。

以下情况必须输出明确的高优先级事件：核心请求 panic、后台任务异常退出、凭证持久化失败、数据文件损坏、日志系统无法写入。

启动日志只输出安全配置摘要：程序版本、监听地址、数据目录、启用平台、日志级别与目标、是否配置代理、各平台是否启用账户或调用方凭证能力、凭证库和 Uni Playlist 存储是否成功打开。不得输出代理认证、Cookie、token 或文件内容。

关闭日志记录关闭原因、仍在运行的任务数量、日志缓冲刷新结果和未完成事务摘要。

## 测试与验收

测试代码提供只初始化一次的 subscriber，字段和脱敏规则与生产一致；测试失败可显示关联日志，`--nocapture` 可查看调试输出，但测试便利不能成为泄露真实凭证的例外。

首个 pre-release 的全端点验收同时检查：

- 每个请求均可通过 `request_id` 关联成功、失败和上游调用；
- 控制台/文件级别、格式、创建、轮转与保留配置生效；
- 异常可定位到平台、操作和错误分类；
- 日志中不存在 Cookie、token、密码、手机号、验证码、签名参数、完整媒体临时地址或其他凭证；
- 关闭 `debug/trace` 后高频事务不会刷屏；
- 服务重启后旧日志与数据文件互不影响。

本阶段只建设后台和日志文件，不制作 Web 日志查看器或管理员前端。
