# 测试版验收与 pre-release 发布标准

首个可公开使用的 pre-release 以路线图阶段 3 为功能截止线，但阶段 3 完成不等于可以立即发布。发布前还必须完成阶段 4 的后台日志与可观测性建设，并对当前全部 HTTP 端点执行一次真实网络验收。

## 功能线

- 网易云音乐项目范围收口；
- QQ 音乐项目范围收口；
- B 站除 BA03–BA07 延期登录链外的当前项目范围收口；
- Uni Playlist 客户端托管模式、服务端多歌单目录和持久化改造完成；
- 酷狗、咪咕、酷我和汽水音乐公开音源补充层完成；
- Uni Playlist 的 Server 与 Client 模式均可导入、混合和播放已有平台资源，并可显式交换而不自动同步；
- resolver 与播放回退存在真实成功链。

B 站延期登录、后四个平台完整账户能力、验证码服务本地 Rust 实现和平台功能扩展候选不阻塞首个 pre-release。

## 唯一端点清单

从实际路由、接口文档和各平台项目范围账本生成一份唯一端点清单，作为发布验收分母。不得只选择近期开发或容易成功的端点。清单须固定到候选发布提交，并记录端点、方法、平台、认证要求、破坏性级别和验收用例。

实际 Router 的原始 `方法 + 路径` 分母保存在 [`acceptance/routes.json`](acceptance/routes.json)。该文件由 Rust 集成测试直接从 `build_router` 提取；路由重复、无法识别或源码与清单不一致都会使全仓测试失败。需要接受路由变更时，显式设置 `TUNEWEAVE_UPDATE_ENDPOINT_INVENTORY=1`，运行 `cargo test -p tuneweave-server --test endpoint_inventory` 并审查差异。PowerShell 7 使用 `$env:TUNEWEAVE_UPDATE_ENDPOINT_INVENTORY='1'` 设置当前进程环境变量；POSIX shell 可把 `TUNEWEAVE_UPDATE_ENDPOINT_INVENTORY=1` 写在命令前。原始路由清单不代替最终验收元数据；平台适用性、认证要求、破坏性级别和验收用例必须在其上完整覆盖后，才能作为候选发布清单。

逐项验证：

- 匿名端点使用真实网络；
- 登录端点使用现有或专用网易云、QQ 和 B 站凭据；
- 调用方凭证分别验证服务器凭证与调用方凭证模式；
- 支持 `server/client/both` 的登录或凭证交付流程分别验证；
- 分页覆盖首页、中间页、末页、空结果、跨上游分页和非法参数；
- 播放/下载验证媒体真实可访问，而非只检查 JSON 中存在 URL；
- 302 验证重定向目标、必要请求头和实际媒体响应；
- 歌词、字幕和元数据验证不是占位值或空壳；
- Server Uni Playlist 验证多歌单目录、创建、读取、元数据修改、删除、导入、重复项、顺序、播放回退和重启恢复；
- Client Uni Playlist 验证来源展开、项目标准化和单项播放均无持久化写入，且无需上传完整歌单；
- `tuneweave_uni_playlist_v1` 验证跨实例交换、Server identity/gzip 导出等价、Client 文档原子导入、重复项与稳定身份不丢失；
- Uni Playlist 验证按歌单独立持久化、失败不覆盖、Windows 中断恢复，且大型歌单修改不再重写全局数据库；
- 账户资料验证 UID、昵称、头像、会员状态和精确账户选择；
- 会话状态、刷新和退出使用现有凭据或专用测试账户；
- 登录失效、权限不足、资源不存在、参数错误和上游失败不能伪装成成功。

会员或付费能力只要求与测试账户真实权益一致。无权益时正确返回试听、降级或权限不足可以通过，不能伪造会员成功。

## 媒体可用性

使用安全 HEAD、Range 或少量媒体读取验证：

- 域名和协议符合白名单；
- 链接未立即失效；
- Referer、Cookie 或其他必要请求头有效；
- 响应包含真实媒体内容；
- 音质、编码和容器与声明一致；
- 试听窗口和会员限制与响应一致；
- 至少一条备用地址或跨平台回退链真实可用。

无必要时不得下载完整歌曲或视频。媒体验证请求也必须遵循域名、重定向、响应体大小和凭证脱敏边界。

## 破坏性操作

歌单、收藏、喜欢、排序、资料修改和 Server Uni Playlist 写操作只能使用隔离测试对象或专用测试账户。测试流程必须创建临时对象、执行变更、读取验证并清理；不得对真实常用歌单、收藏夹或账户资料执行不可逆测试。Client 模式必须使用专用空数据目录，并确认 materialize、播放和回退后没有生成 Uni Playlist 持久化文件。

## 日志与安全

发布验收同步执行 [`observability.md`](observability.md) 的关联、轮转、配置和脱敏检查。尤其确认日志中不存在 Cookie、token、密码、手机号、验证码、签名参数、完整临时媒体地址或调用方凭证。

## 发布报告

第一次 pre-release 前生成带日期和提交 SHA 的报告，至少包含：

- 测试环境、服务版本和提交；
- 使用的平台及账户类型，不记录具体秘密；
- 端点总数，以及通过、预期受限、跳过和失败数量；
- 失败原因、已知上游限制和不阻塞测试版的问题；
- 播放、下载、302、备用地址和回退链抽样结果；
- Uni Playlist Server/Client、交换文档和按歌单存储验收结果；
- 日志创建、轮转、关联和脱敏检查结果。

核心端点存在无法解释的失败时不得发布。非核心端点因临时风控、账户无权益或区域限制不能达到成功态时，必须在报告中明确标记，不能静默计为通过。满足功能线、可观测性和全端点真实验收后，才可以生成 pre-release。
