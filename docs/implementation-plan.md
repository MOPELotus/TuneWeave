# TuneWeave 路线图与项目范围

TuneWeave 为六个媒体平台提供统一、可扩展的 Rust HTTP API。“项目范围（Project Scope）”是每个平台在产品定位内计划完成的全部正式能力；完成项目范围即视为平台完成，不要求继续复刻参考项目的全部公开接口。

## 正式发布前的兼容策略

首个正式 Release 发布前，仓库中的接口、模型、存储格式、配置和内部模块都属于开发中契约。发现更合适的设计时可以直接做不兼容调整，只要求全新部署能够正确启动、使用和完成验收；不为开发快照提供数据迁移、旧端点转发、旧字段别名、双写或旧模块保留层。确需保留的 `legacy/modern`、`v1/v2` 等名称只表示目标平台当前同时存在且仍属于项目范围的协议分支，不表示 TuneWeave 自身对开发版本的兼容承诺。正式 Release 后再按语义化版本和明确的升级策略评估兼容与迁移。

## 项目范围

项目范围通常包括：

- 请求协议、签名、设备身份、分页与错误映射；
- 登录、会话、`(platform, account)` 多账户和调用方托管凭证；
- 账户 UID、昵称、头像、会员及播放权益等必要展示字段；
- 搜索、建议、热搜及稳定资源身份；
- 与媒体使用直接相关的歌曲、视频、歌手、专辑、歌单、收藏夹和合集；
- 普通/逐字歌词、翻译、罗马音以及 B 站字幕时间轴；
- 播放、下载、音质、清晰度、试听、必要请求头和链接有效期；
- 个人歌单、喜欢/收藏列表、Uni Playlist 导入与严格跨平台回退。

私信、纯社交关系、动态发布、装扮、商城、创作者后台及其他不能直接增强媒体检索、整理或播放的能力不属于默认项目范围。已经发现但不在范围内的协议只登记到 `docs/coverage/extensions/`，使用 `candidate/selected/implemented/rejected`；候选池没有完成率、清零要求或固定实施时间。

项目范围账本使用 `pending/deferred/partial/implemented/verified`，并且是唯一的平台完成度分母：

- [网易云音乐](coverage/netease-scope.md)
- [QQ 音乐](coverage/qq-scope.md)
- [B 站](coverage/bilibili-scope.md)
- [Uni Playlist](coverage/uni-playlist.md)
- [酷狗](coverage/kugou-scope.md)
- [咪咕](coverage/migu-scope.md)

后续接入酷我时建立 `kuwo-scope.md`。

## 阶段 1：前三个平台项目范围收口

依次收口网易云音乐、QQ 音乐与 B 站当前主线，优先消除会阻塞搜索、列表、Uni Playlist、歌词/字幕、播放和下载的缺口。B 站 BA03–BA07（GeeTest、密码登录、国家/地区区号、短信发送及短信登录）保留在最终项目范围中，但维持 `deferred`，不阻塞当前主线完成。

同一阶段内部按依赖和使用频率推进：

1. 平台协议、签名、设备身份和错误映射；
2. 登录、会话、多账户和调用方托管凭证；
3. 直接搜索；
4. 个人歌单、喜欢/收藏及 Uni Playlist 导入；
5. 普通/逐字歌词、翻译、罗马音或字幕；
6. 播放、下载、权益和跨平台回退；
7. 歌单、专辑、歌手、榜单、视频、播客与电台等目录详情；
8. 仍属于普通媒体后端的低频能力。

## 阶段 2：Uni Playlist 客户端托管与存储改造

当前 Uni Playlist 已支持多个独立歌单、分页目录和按歌单拆分存储。本阶段在 B 站当前项目范围主线收口后实施，不阻塞阶段 1：

- 保留现有 `server` 模式；分页目录、元数据修改和明确删除已经完成；
- 新增不持久化歌单或项目的 `client` 模式；版本化 `tuneweave_uni_playlist_v1` 强类型文档、无状态来源展开、批量项目标准化和单项目播放/跨平台回退已经完成；
- 提供 Server 导出与 Client 文档原子导入，两种所有权模式只显式复制，不提供 `both` 自动同步；
- 按歌单拆分、无额外数据库依赖的目录后端和生产入口切换已经完成；开发期旧存储格式不进入兼容范围。

完整所有权、接口候选、文档安全边界、存储方案与验收标准见 [Uni Playlist 客户端托管与存储设计](uni-playlist-ownership.md)。完成状态以 [Uni Playlist 实施账本](coverage/uni-playlist.md) 为准。

## 阶段 3：酷狗、咪咕、酷我公开音源补充层

先实现三个平台无需登录即可直接提高播放成功率的能力：

- 歌曲搜索、稳定身份和歌曲详情；
- 标题、歌手、专辑、时长、ISRC、版本与音质元数据；
- 歌词及可用播放/下载地址；
- 必要请求头、链接有效期、试听窗口和实际音质；
- 统一播放、下载、302 与跨平台 resolver；
- 公开歌单或集合的 Uni Playlist 导入。

该层可以按端点实际可用性并行验证，不要求先完成登录和个人音乐库。真实可用、无需登录且不绕过访问控制的高品质分支可以纳入，但不得伪造会员权益。阶段 3 完成即达到首个测试版的功能线。

## 阶段 4：后台日志与测试版可观测性

公开音源补充层完成后立即建设控制台与文件双输出、非阻塞写入、轮转保留、结构化字段、请求关联、上游调用摘要、登录事务状态、启动/关闭摘要和统一错误链。完整配置、字段及脱敏规则见[后台日志与可观测性规范](observability.md)。

阶段 4 不扩大平台功能范围，但它与一次全端点真实网络验收共同构成首个公开 pre-release 的发布前置。验收清单、媒体探测、破坏性操作隔离及报告格式见[测试版验收与发布标准](pre-release-acceptance.md)。

## 阶段 5：B 站延期登录链

实施 BA03–BA07：GeeTest challenge、外部验证码 provider 链、密码登录、国家/地区区号、短信发送和短信登录。严格沿用 [`bilibili-captcha-providers.md`](bilibili-captcha-providers.md) 的事务同意、顺序切换、失败分类、challenge 刷新、限流、重试和脱敏边界。

## 阶段 6–8：后三个平台项目范围

1. 酷狗项目范围：在公开音源层上补协议底座、登录/会话/多账户、调用方凭证、账户资料与会员状态、完整媒体搜索、个人歌单/喜欢、Uni 导入和登录权益播放。
2. 咪咕项目范围：补移动统一账号、短信验证与多业务身份的独立强类型模型，以及同等的账户、媒体、列表、歌词、播放、权益和回退能力。
3. 酷我项目范围：公开音源层已先完成实时协议审查并开始接入；长期失效端点只记录能力边界，不以占位数据或离线解析冒充可用。当前状态见 [`coverage/kuwo-scope.md`](coverage/kuwo-scope.md)。

三个平台均不因参考项目存在私信、动态、直播互动、装扮或商城接口而扩大范围。

## 阶段 9：验证码服务本地 Rust 实现

六个平台项目范围稳定后，依次实现 GT-Manual 与 test_nine 的本地 Rust 版本。GT-Manual 优先完成任务注册、人工页面、结果轮询、回收、限流与安全控制；test_nine 随后使用稳定推理运行库承载既有模型、图像处理和轨迹逻辑，不重新训练模型，也不依赖 Python 服务。外部 provider 仍可保留为部署方可配置选项。

## 阶段 10：平台功能扩展

所有旧“全量阶段”合并为无固定时间、分母和完成率的平台功能扩展阶段。仅在真实调用方需求、项目范围维护需要、显著媒体收益或适合 `/v1/extensions/{platform}` 的平台特有能力出现时，从候选池选择一组能力，建立独立任务与验收边界。不得以“参考项目存在该接口”或“候选池尚未清零”作为实施理由。

## 项目完成与测试版边界

正式项目完成要求六个平台项目范围达到预定状态，Uni Playlist、跨平台回退、公开及账户音源、验证码链、日志、错误模型、凭证安全、真实网络验收和文档全部稳定。扩展候选池仍有未实现条目不影响完成状态。

首个 pre-release 的功能截止线是阶段 3：网易云和 QQ 项目范围收口、B 站除延期登录链外的当前范围收口、Uni Playlist `server/client` 所有权模式与服务端存储改造完成、后三个平台公开音源层完成，并且 resolver 能对服务端及客户端托管项目真实回退。发布前还必须完成阶段 4 和全端点发布验收；B 站延期登录、后三个平台完整账户能力、验证码本地实现和扩展候选均不阻塞首个测试版。

## 长期架构约束

服务器账户按 `(platform, account)` 隔离；登录统一支持 `credential_mode=server|client|both`，完整契约见 [`credential-ownership.md`](credential-ownership.md)。Uni Playlist 只规划 `server/client`，不照搬凭证的 `both`：服务端资源使用 `uni:<id>`，客户端文档身份不会隐式成为服务端资源，两者只通过显式导出/导入复制。两种模式都只保存类型化资源、来源、顺序、重复项与元数据快照，媒体字节和凭证不得进入歌单数据。参考源码只作为协议资料，不能机械翻译；平台目标、代理、请求头和重定向范围始终由 provider 固定控制。
