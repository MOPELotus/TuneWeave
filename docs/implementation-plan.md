# TuneWeave 路线图与范围

TuneWeave 最终完整覆盖参考项目中属于本项目范围的公开 API、参数和行为分支。阶段只决定实现顺序，不会把低频、平台特有或难以统一的能力从最终范围中删除；缺少合理统一语义的能力进入 `/v1/extensions/{platform}`。

## 阶段顺序

1. 网易云 Basic
2. Uni Playlist
3. QQ 音乐 Basic
4. B 站 Basic
5. 酷狗、咪咕、酷我公开音源补充层
6. B 站 GeeTest、密码与短信登录链
7. 网易云全量
8. QQ 音乐全量
9. B 站音视频范围内全量
10. 酷狗、咪咕、酷我其余全量能力

B 站范围包括登录、账户、视频与音频播放、公开合集、系列、收藏夹及相关列表；专栏、直播、漫画、游戏等与音视频播放无关的业务不纳入。酷我在接入前逐项验证当前接口可用性，失效端点保留明确能力边界，不用占位数据冒充成功。

## Basic 优先级

Basic 按播放器实际依赖和使用频率排序：

1. 平台请求、签名、设备身份和错误映射等必要底座。
2. 登录、多账户、会话状态和调用方托管凭证。
3. 单曲或视频直接搜索。
4. 个人歌单、喜欢/收藏列表及 Uni Playlist 导入。
5. 普通、逐字、翻译和罗马音歌词；B 站对应字幕时间轴。
6. 播放、下载、音质、VIP/试听权益和跨平台回退。
7. 歌单、专辑、歌手、榜单、MV/视频、播客、电台等目录与详情。
8. 仍属于普通播放器的低频展示、云盘、推荐和平台扩展能力。

云盘、播客、MV、VIP 状态和付费内容的合法播放链属于 Basic。纯社交动态、私信、粉丝关系等放入平台全量阶段；已经实现的评论能力继续保留。

B 站二维码登录、会话与多账户仍属于 Basic 底座；GeeTest 人机验证、密码登录、国家/地区区号、短信发送及短信验证码登录不阻塞收藏夹、视频信息和播放链收口，统一在公开音源补充层之后实施。验证码链的 provider、安全确认和限流契约见 [`bilibili-captcha-providers.md`](bilibili-captcha-providers.md)。

各阶段的接口覆盖状态见 [`docs/coverage`](coverage/)。网易云和 QQ 的完整逐项账本分别以参考项目公开模块与公开方法为分母；B 站 Basic 以 BBDown 和 B 站接口文档中与登录、列表、视频及音频相关的能力为基线。

## 公开音源补充层

酷狗、咪咕和酷我在前三个平台进入全量阶段前，先实现可直接增强播放成功率的公开能力：

- 匿名或公开可用的歌曲搜索与稳定资源身份；
- 用于严格匹配的歌曲、歌手、专辑、时长、ISRC、版本和音质元数据；
- 公开歌曲详情、歌词及可用的播放/下载地址；
- 统一流、下载、302 和跨平台 resolver 接入；
- 将公开歌曲直接加入 Uni Playlist，并把公开歌单或收藏集合接入 Uni 导入；
- 原平台不可播时作为有序回退候选，同时保留匹配分数、实际音质、试听窗口、必要请求头和失败原因。

这一阶段不要求先完成登录、账户资料或个人库。若参考项目提供真实可用、无需登录且不绕过访问控制的高品质或会员歌曲播放能力，可作为公开音源分支纳入；TuneWeave 不伪造会员权益，也不把失效或受限地址标记为可播放。

公开音源层完成后，先实现 B 站延期的 GeeTest、密码与短信登录链，再让网易云、QQ 和 B 站进入全量阶段；酷狗、咪咕和酷我的登录、多账户、个人库、写操作及其他公开 API 在其余全量阶段逐项补齐。

## 多平台账户与凭证

服务器托管账户以 `(platform, account)` 隔离，同一平台可以保存多个账号，不存在的别名不得回退 `default`。登录统一支持 `credential_mode=server|client|both`：调用方可选择由服务器保存、只接收版本化凭证，或保存并接收同一凭证代际。跨平台请求可组合不同平台的服务器账户与调用方凭证，同一平台同时指定两种来源时在访问上游前拒绝。

完整契约见 [`credential-ownership.md`](credential-ownership.md)。密码、验证码、Cookie、token 和设备密钥不得进入普通日志、错误或响应；平台请求目标、代理和请求头始终由 provider 控制。

## Uni Playlist

Uni Playlist 是独立于音乐平台的跨平台歌单，公开引用为 `uni:<opaque-id>`。它支持：

- 通过 `ref+type+account?` 或 `platform+type+id+account?` 导入公开、账户可见或本地 Uni 集合，并完整遍历来源分页；
- 手工添加任意平台的歌曲、MV/视频音频、播客节目、广播电台等可播放资源；
- 在同一歌单中混合多个平台并保留来源、顺序、重复项、内容类型和元数据快照；
- 优先播放原始平台，也可指定播放平台或按有序平台列表执行严格匹配回退；
- 当自动匹配不到替代源时，由用户添加另一平台的可播放项目作为显式替代来源；
- 按目标平台分别选择账户或调用方凭证，不跨平台借用登录态。

媒体字节和平台凭证不写入 Uni Playlist 数据库。平台歌单与 Uni Playlist 共用 `/v1/playlists` 读取及播放端点，调用方不需要维护第二套协议。
